# 技术说明

实现层面的细节，配合主 [`README.md`](../README.md) 阅读。主 README 讲"是什么、怎么用"，这里讲"怎么做的"。

## 渲染与窗口

- **纯 Go 原生窗口**：`ui.View` 构建整个界面；构建 tag `mygo_nowebview` 让 MyGo 进入 native-only 模式，避免引入 WebView 运行时。
- **虚拟化网格**：`grid.go` 只对可见区域绘制卡片、缩略图、文件名、选中描边和悬停阴影，不为几千张图片创建控件。
- **自绘窗口**：`TitleBarHidden` + `HideWindowButtons`，48 DIP 标题栏承担拖动、双击最大化、最小化/最大化/全屏/关闭和 Windows 11 snap layouts；全屏状态由窗口自身维护。
- **设备缩放**：界面按 DIP 布局，渲染器按显示器缩放绘制（PerMonitorV2）。查看器的 `100%` 因此要除以窗口的设备缩放（`GetDpiForWindow / 96`）才是真正的 1 个图像像素对 1 个设备像素，百分比读数同理。

## 缩略图管线

Windows Imaging Component（WIC）优先读取 JPEG/PNG/TIFF/BMP/GIF/WebP。尺寸远大于卡片时先让解码器只解一半 / 四分之一 / 八分之一的像素（`IWICBitmapSourceTransform`，JPEG 的 DCT 缩放；24 MP 出 220 px 卡片实测 2.3× 快，也不再为每张图申请全分辨率中间位图）；解码器不提供缩放或尺寸本来就小时退回内嵌缩略图与 `IWICBitmapScaler`（HighQualityCubic）。HEIC/RAW/ICO 优先系统 Shell provider，普通 JPEG 不依赖 Shell；WIC/Shell 失败自动回退纯 Go。

EXIF IFD1 内嵌缩略图先发 160 px preview，最终图到达后替换。磁盘 JPEG q84、`v2` 后端版本、内存 1200 条目 + 512 MB 字节双上限、近似 LRU。缓存按用途分两个目录：`thumbs`（网格卡片）与 `previews`（查看器 2560 预览），共用设置里的容量额度，启动时把旧版混在 `thumbs` 里的预览文件搬到 `previews`。透明图预乘后合成到中性底色。

**并发**：可见卡片排完之后，后台以低优先级继续把当前文件夹剩余的缩略图写进磁盘缓存（只写缓存、不保留位图）：静止时四路，滚动时收到两路，让正在看的卡片先拿到 worker；切换文件夹或关闭开关立即停止；文件夹张数超过设置的上限（默认 200）时不做这一步，因为可见卡片本来就覆盖不了整个文件夹。解码 worker 数按机器定：最多 10 路，内存不到 8 GB 时退回 6 路（PNG 和未知格式走全图解码，一张 24 MP 就是 96 MB 位图，路数多了放不下）；实测 20 线程机器上吞吐到 10 路才饱和，16 路反而略降。

**缓存快车道**：磁盘上已存在的卡片走独立的一路（3 个 worker）读回，不再排在整张解码后面，回看旧文件夹不用等。刚解码出来的卡片直接用那份像素建位图，不再把自己刚写的 JPEG 解一遍，缓存文件在图片上屏之后才落盘。

## 查看器管线

最长边 2560、`ApproxBiLinear` 快缩放、`ui.NewBitmap` 直接上屏、JPEG q90 异步写缓存（存 `previews` 目录）；缓存命中走 JPEG 解码后更新一个持久 bitmap 槽，避免每次打开都新建 17 MB 纹理。

邻居预加载单 worker、384 MB 字节预算、当前图跳过，只取 2560 预览；当前图的原图在邻居预览排空后自动后台解码（全局串行一张，切图即放弃队列里的其余解码）；1:1 对任意尺寸按需解码原图，当前图保留全分辨率 bitmap，关闭/切图立即释放并回收大图临时堆。长边不超过 2560 的图预览就是原图，解原图那一步有意跳过——那只会多占内存。

## 远程读取层

`remote.go` 定义统一后端接口（列目录、打开流、HTTP 转发、关闭），SMB2 用 `go-smb2` 在进程内建会话，WebDAV 用 `net/http` 发 PROPFIND 与带 Range 的 GET；连接按「主机 + 共享 + 账号」进池，闲置 90 秒回收，回收时的登出带 2 秒上限，服务器不响应就直接断开底层 TCP。

路径是虚拟的（`smb://主机/共享/子目录`），`cleanDisplayPath` 让虚拟路径绕开 `filepath.Clean`（否则会变成 `smb:\主机\...`），缩略图、预览、EXIF、ICO 解码都改走 `openItemFile` 拿流，所以远程与本地共用同一套解码管线。

**远程视频**：Media Foundation 能用 `http://` 但用不了应用私有的 SMB 会话，因此在 `127.0.0.1:0` 上起一个只服务远程路径的 HTTP 服务（随机端口、随机路径令牌、只接受 GET/HEAD），把 `Range` 原样转给后端，空闲 3 分钟自动关闭；ffmpeg 取帧也把该 URL 当输入。

**远程前缀**：远程文件只读一次 256 KiB 前缀，尺寸与 EXIF 都从这段数据里出；图片卡片的补载也复用这份前缀——内嵌缩略图够大（不小于卡片四分之三）就直接当最终图，整张照片不必过网。

## 异步媒体信息

尺寸、EXIF、MP4/MOV sample table、帧率和滚动码率在后台读取；视频先取容器 metadata，再启动播放器，避免文件句柄冲突。

## 更新链路

`mygo.json` 配置 GitHub 更新源与公钥；`mygo.Updater.Check` 返回新版本，`Update.Install` 下载并校验签名归档或增量补丁，成功后 `mygo.App.Relaunch()`。Ed25519 私钥只存在于发布者的本地密钥文件与 GitHub secret 中，**不得重新生成**——换了密钥，所有已安装的旧版本都无法再验证新更新。

完整步骤见 [`发布流程.md`](发布流程.md)。

## 调试端点

`debug.go` 只在 `-tags "debug mygo_nowebview"` 时编译，release 构建不包含。它在 `127.0.0.1:47831` 上提供 `/ready`、`/state`、`/shot`、`/command`，用于自动化验证界面状态与截图。`/state` 会报告查看器画质、设备缩放、缓存命中率等诊断字段。
