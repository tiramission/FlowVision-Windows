# 缩略图测试语料说明

- 生成日期：2026-11-26
- 生成脚本：`tools/make_thumb_corpus.py`
- 语料目录：`testdata/thumb-corpus`（已加入 `.gitignore`，不随仓库提交）
- 体量：470 个文件，2.27 GiB
- 用途：本地性能基准、格式矩阵、方向矩阵、两阶段渲染和回滚验收；不是单元测试的必跑资产

## 1. 目录结构

| 路径 | 内容 | 数量/规格 |
|---|---|---|
| `orientation/` | EXIF Orientation 1–8 | 8 张 JPEG，2400×1600 主图 |
| `formats/` | 格式矩阵 | 14 个样本，见下表 |
| `masters/` | 24 MP 合成主图 | 12 张，约 4–6 MB/张 |
| `dirs/24` | 24 MP 图目录 | 24 张 |
| `dirs/100` | 24 MP 图目录 | 100 张 |
| `dirs/300` | 24 MP 图目录 | 300 张 |
| `sizes/` | 单张尺寸样本 | `12mp.jpg`、`48mp.jpg` |
| `real/` | 真实照片和 RAW | 8 张 JPEG + 1 张 DNG |
| `manifest.json` | 生成时清单（路径、字节数、截断 sha256） | 仅覆盖生成器产出；后加真实样本不在清单 |

`dirs/24`、`dirs/100` 是 `dirs/300` 的前缀子集，便于同一批图对比不同目录规模。`masters/` 的 12 张主图会循环复制到三个目录。

## 3. 合成图特征

- 24 MP 主图为 6000×4000，叠加多尺度渐变、棋盘/条纹、细颗粒噪声和局部高频纹理，避免“纯渐变图”让缩放核看起来过好。
- JPEG 质量约 88–92，文件 4–6 MB；目录内文件大小有波动，避免所有任务同一耗时。
- 方向样本在像素层写入“TOP/LEFT”等标记，并写 EXIF Orientation 1–8；实机截图可直接看出 5–8 是否被转成竖向。
- IFD1 内嵌缩略图由脚本注入：24 张 `dirs/*` 中一半带 160×106 的 JPEG thumbnail，用于验证 preview 两阶段；`img-000.jpg` 内嵌约 6266 bytes。
- 透明 PNG 使用从全透明到不透明的对角渐变，便于检查预乘 alpha 和底色合成。

## 5. 重新生成

```powershell
python tools/make_thumb_corpus.py --full
```

`--quick` 只生成小规模语料，适合 CI/快速冒烟；`--full` 生成上述完整目录。脚本需要 Pillow、numpy、piexif；HEIC 写入需要 pillow-heif（可选）。真实照片和 DNG 不包含在脚本内，需按上表 URL 单独下载到 `real/`。

## 6. 使用约定

- `TestThumbBaseline`、`TestFormatRender`、`TestBackendQuality`、`TestCorpusOrientation` 通过 `FLOWVISION_THUMB_CORPUS` 定位语料；默认 `testdata/thumb-corpus`。
- 性能数字只在本地 NVMe、6 worker、目标高度 220 下采集；换机器/换盘不能直接横向比较。
- 语料体积大，不进入 git；发布包和 CI 不依赖它。需要复现时按脚本和 URL 重建。
- `manifest.json` 是生成时快照，后加的真实样本不在其中，避免把下载文件误认为生成器产物。
