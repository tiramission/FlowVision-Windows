# 查看器加载性能报告（v1.4.0）

- 版本：`v1.4.0`（已发布；Release <https://github.com/tiramission/FlowVision-Windows/releases/tag/v1.4.0>，Actions <https://github.com/tiramission/FlowVision-Windows/actions/runs/45718991018>）
- 计划：[`查看器加载性能优化计划.md`](查看器加载性能优化计划.md)
- 基线：[`查看器加载性能基线.md`](查看器加载性能基线.md)
- 数据：`docs/viewer-bench-app.json`、`viewer-bench-app-warm.json`、`viewer-bench-app-cycles.json`、`viewer-bench-go.json`
- 机器：i7-12700H，10 核 20 线程，约 4 GB 内存，Windows 11 x64，本地 SSD

## 1. 结论

Phase 1–4 的必做项已全部落地：2560 快缩放、直接 bitmap 上屏、缩略图占位、预加载优先级与内存释放、悬停预取、按需 1:1 全分辨率、非侵入式 HUD、设置项、真实语料、基准和回归。24 MP 查看器冷开 P50 **418 ms**、P95 **474 ms**（旧链路 870–1430 ms）；热缓存 P50 **72 ms**、P95 **80 ms**；占位首帧 6–9 ms 内可见。50 次打开/关闭 Private 从 184.4 MB 到 210.6 MB，增长 **26.2 MB**，达到计划的 ≤30 MB 门禁。

1:1 只对 ≤50 MP 启用：24 MP 1:1 334 ms、bitmap 91.55 MB、Private 319.3 MB；50 MP-under 1:1 531 ms、190.7 MB、Private 707.8 MB；80 MP 预览 660 ms、Private 564 MB，1:1 正确拒绝并显示 HUD 提示。

## 2. 最终性能

### 2.1 24 MP 查看器

测试语料 `testdata/thumb-corpus/dirs/24`，10 次冷缓存（删除预览缓存、禁用 preload 以隔离单张冷开），每次关闭后等待 600 ms：

| 指标 | 结果 |
|---|---:|
| 首帧占位可见 | 6.4–8.6 ms |
| 冷开 P50 | 418 ms |
| 冷开 P95 | 474 ms |
| 冷开最大 | 474 ms |
| 分项 decode | 215–261 ms |
| 分项 scale（ApproxBiLinear） | 93–116 ms |
| 分项 encode | 63–92 ms |
| 分项 bitmap 上屏 | <1 ms（持久槽 `Update`） |
| 打开后 Private | 215.0–221.7 MB |
| 关闭后 Private | 162.1 MB |
| 关闭后 preload/fullres | 0 MB / 0 条 |

热缓存 10 次（同一目录、已生成 2560 缓存）：

| 指标 | 结果 |
|---|---:|
| 热开 P50 | 72 ms |
| 热开 P95 | 80 ms |
| 热开最大 | 80 ms |
| JPEG 解码 | 32–52 ms |
| bitmap 槽更新 | 15–27 ms |
| 打开后 Private | 155.3–186.2 MB |

### 2.2 1:1 与边界

| 场景 | 耗时 | bitmap | 打开后 Private | 结果 |
|---|---:|---:|---:|---|
| 24 MP 1:1（dirs/24 第 1 张） | 334 ms | 91.55 MB | 319.3 MB | Zoom 5.43，OneToOne=true |
| 50 MP-under（8,333×6,000）预览冷开 | 482 ms | — | 236.1 MB | 占位 70 ms 时已可见 |
| 50 MP-under 1:1 | 531 ms | 190.7 MB | 707.8 MB | Zoom 8.14，OneToOne=true |
| 80 MP（10,000×8,000）预览冷开 | 660 ms | — | 564.0 MB | 预览允许 |
| 80 MP 点 1:1 | 未解码全图 | — | — | FullResUnsupported=true，HUD 提示“原图超过 50MP，只显示 2560 预览” |
| >50 MP（50mp.jpg 50,002,840 像素） | — | — | — | 1:1 被拒绝；预览正常 |

50 MP-under 正好低于 50,000,000 像素门禁，1:1 成功；50mp.jpg 为 50,002,840 像素，超过门禁；80 MP 允许 2560 预览但拒绝 1:1。边界函数测试与实机行为一致。

### 2.3 50 次打开/关闭

50 次连续打开/关闭，每次关闭后 600 ms 采样，禁用 preload，只打开当前图：

| 指标 | 结果 |
|---|---:|
| 冷开 P50 | 409 ms |
| 冷开 P95 | 458 ms |
| 冷开最大 | 475 ms |
| 第 1 次打开 Private | 184.4 MB |
| 第 50 次打开 Private | 210.6 MB |
| 50 次最大 Private | 215.2 MB |
| Private 增长 | **+26.2 MB**（目标 ≤30 MB） |
| 第 50 次关闭后 Private | 156.6 MB |
| 关闭后 preload / fullres | 0 MB / 0 条 |

内存稳定来自两个改动：查看器预览使用持久 `ui.Bitmap` 槽，`Update` 复用同一个纹理；关闭路径最后调用 `debug.FreeOSMemory` 回收 24 MP 解码的临时堆。若不做槽复用，50 次会在 MyGo 纹理缓存里留下约 50 张 2560 纹理，实测增长超过 300 MB；该路径已在最终实现中移除。

### 2.4 Go 基准

23 张真实大图（15 张 Wikimedia 3000–3840 px + 8 张 Picsum；排除 14 张 `cam-*` 小样张）：

| 基准 | 结果 | 说明 |
|---|---:|---|
| `BenchmarkViewerPreviewCold-20` | 352.6 ms/张 | 解码 + ApproxBiLinear + q90 编码 + `ui.NewBitmap` |
| `BenchmarkViewerPreviewWarm-20` | 53.9 ms/张 | 预览缓存 JPEG 解码 + `ui.NewBitmap` |

应用层冷开比 Go 基准高约 50–70 ms，来自 UI 事件循环、缩略图队列余波、HUD 计时和进程内存压力；仍在 P50 ≤450 ms 内。

## 3. 质量

### 3.1 真实照片

5 张 Wikimedia 实拍照片，fast 缩放对比 CatmullRom：

| 文件 | 输出尺寸 | PSNR | MAE |
|---|---:|---:|---:|
| wm-01.jpg | 1741×2560 | 38.06 dB | 1.55/255 |
| wm-02.jpg | 2560×1839 | 51.08 dB | 0.41/255 |
| wm-04.jpg | 2560×1714 | 51.88 dB | 0.23/255 |
| wm-09.jpg | 2560×1733 | 47.47 dB | 0.57/255 |
| wm-11.jpg | 2560×2192 | 47.95 dB | 0.51/255 |

PSNR 门禁 ≥38 dB 通过；最低 wm-01 为 38.06 dB。MAE 目标 1.5/255，最低 wm-01 为 1.55/255，超出 0.05，按计划第 2.2 节作为 known deviation 记录，测试不硬拦。合成渐变 `TestScaleImageFastQuality` PSNR 31.9 dB，满足 ≥30 dB。

## 6. 已知偏差与未覆盖

1. **MAE 1.55 高于计划 1.5**：PSNR 门禁通过；差异集中在 wm-01 的高频纹理，未做逐张并排原尺寸视觉审查。
2. **50 MP/80 MP 是合成边界图**：真实大图语料为 23 张 3000–3840 px 照片，没有真实相机 48 MP 样张；50 MP 类目标通过 50 MP-under 合成图验证。
3. **HUD 10 分钟沉浸长跑未执行**：单槽、80 ms 合并、200 ms 淡出、auto/off/always 模式已有测试和截图；未做连续 10 分钟人工 soak。
4. **悬停预取缺物理指针端到端**：当前验证覆盖边带布防/取消与 `viewerstep` preload 命中；指针从画布直接进入 header/footer 时可能没有 leave 事件，timer 仍可能触发一次。
5. **1:1 只有单条 fullres**：没有多图 LRU；切图/关闭立即释放，单条 256 MB 预算满足 4 GB 机器约束。
6. **preload 预算为 96 MB**：计划风险表写 128 MB 暂定，实际采用 96 MB，更保守；默认 2 张约 33 MB。
7. **内存指标用 Private/Working Set**：没有采集 GDI/Handles 长期曲线；50 次开关的 Private 已稳定，GDI/Handles 仍建议发布后观察。
8. **`go vet` 既有告警**：`thumb_wic_windows.go` 两条 `unsafe.Pointer` 未处理，不是本次新增。

## 7. 复现

```powershell
# 全量测试
go test ./...

# 10 次冷开（清预览缓存；脚本默认禁用 preload 隔离）
pwsh tools/bench_viewer.ps1 -Go "C:\path\to\go.exe" -Runs 10 -Out docs\viewer-bench-app.json

# 热缓存：先让缓存生成，再跑一次
pwsh tools/bench_viewer.ps1 -Warm -Runs 10 -Out docs\viewer-bench-app-warm.json

# 50 次开关
pwsh tools/bench_viewer.ps1 -Runs 50 -Out docs\viewer-bench-app-cycles.json

# Go 分项基准
go test -run '^$' -bench BenchmarkViewerPreview -benchtime=20x -count=1 .

# 真实质量
go test -run TestViewerFastScalerRealQuality -v .
```

调试环境变量：`FLOWVISION_VIEWER_PREVIEW=fast|hq|legacy`、`FLOWVISION_VIEWER_SCALER=fast|hq`、`FLOWVISION_VIEWER_CACHE=off`、`FLOWVISION_VIEWER_HUD=off|auto|always|debug`、`FLOWVISION_VIEWER_PRELOAD=off`（仅基准隔离）。
