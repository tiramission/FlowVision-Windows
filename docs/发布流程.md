# 发布与更新流程

本项目的 Windows 发布使用 MyGo 的标准流程：`mygo build` 生成按用户安装包、签名更新归档和 `update-windows-amd64.json`；GitHub Actions 在推送 `v*` 标签时构建并发布。应用内通过 MyGo `native` updater 检查、校验、安装并重启。

## 1. 一次性配置

### 仓库

更新源使用公开仓库的 GitHub Releases。`mygo.json` 中的 `updates.github` 必须是一个匿名可读的仓库；当前配置为 `tiramission/FlowVision-Windows`，仓库已设为 public。

### 更新密钥

更新签名使用 Ed25519 密钥对，由 `mygo keygen` 生成：

- 私钥：`mygo-update.key`，只进入 GitHub Actions secret 和离线备份，不进入仓库。
- 公钥：`mygo-update.pub`，已经写入 `mygo.json` 的 `updates.publicKey`。

当前备份目录：

```text
C:\Users\WDAGUtilityAccount\Desktop\主机同步\FlowVision-Update-Keys\
  mygo-update.key
  mygo-update.pub
  README.md
```

GitHub secret 名称：

```text
MYGO_UPDATER_PRIVATE_KEY
```

设置命令（只在本机执行，不要把私钥贴到终端输出）：

```powershell
Get-Content -Raw "$env:USERPROFILE\Desktop\主机同步\FlowVision-Update-Keys\mygo-update.key" |
  gh secret set MYGO_UPDATER_PRIVATE_KEY --repo tiramission/FlowVision-Windows
```

更换机器后，从备份目录恢复私钥，再设置 secret。**不要重新生成密钥对**：已安装的应用只接受当前公钥签名的更新，换了密钥会让旧版本无法更新。

### Windows 代码签名（可选）

更新签名与 Windows 代码签名是两件事。当前没有配置 `.pfx` 证书，安装包仍可能触发 SmartScreen 警告；如需消除警告，按 MyGo 文档增加 `windows.certificate` 和 `WINDOWS_CERTIFICATE` / `MYGO_WINDOWS_CERTIFICATE_PASSWORD` secrets。更新包本身始终由 Ed25519 密钥签名并校验。

## 2. 每次发布

1. 修改 `mygo.json` 的 `version`。
2. 同步修改 `main.go` 的 `devVersion`（仅直接 `go build` 的兜底；打包版本以 `mygo.json` 为准）。
3. 在 `CHANGELOG.md` 增加对应章节，例如：

   ```markdown
   ## [1.3.0] - 2026-12-01

   ### Added
   - ...
   ```

4. 本地检查：

   ```powershell
   go test -count=1 -tags mygo_nowebview .
   $env:GOFLAGS = "-tags=mygo_nowebview"
   go tool mygo build -platform windows/amd64
   ```

   本地完整构建需要 `MYGO_UPDATER_PRIVATE_KEY` 或 `updates.privateKey`；没有密钥时只构建应用，不生成更新文件。

5. 提交并推送标签：

   ```powershell
   git add mygo.json main.go CHANGELOG.md
   git commit -m "Release v1.3.0"
   git tag v1.3.0
   git push origin main
   git push origin v1.3.0
   ```

6. GitHub Actions 自动执行：

   - 校验 tag 与 `mygo.json` 版本一致；
   - 创建 `v1.3.0` 草稿 Release；
   - `go tool mygo build -platform windows/amd64 -upload` 构建安装包、更新归档、`update-windows-amd64.json`、`install.ps1`、`SHA256SUMS`；
   - 上传完成后把草稿 Release 发布为正式版本。

7. 发布后验证：

   - Release 资产包含 `flowvision-setup-1.3.0-amd64.exe`、`flowvision-1.3.0-windows-amd64.tar.gz`、`update-windows-amd64.json`；
   - `https://github.com/tiramission/FlowVision-Windows/releases/latest/download/update-windows-amd64.json` 可匿名访问；
   - 安装版应用点标题栏的“检查更新”，或在设置 → 软件更新、关于窗口里检查；发现新版本后下载并重启。

## 3. 本地构建产物

`mygo.json` 的 `out` 为 `build`，Windows 构建位于：

```text
build\windows-amd64\
  FlowVision.exe
  flowvision-setup-<version>-amd64.exe
  flowvision-<version>-windows-amd64.tar.gz
  update-windows-amd64.json
  install.ps1
  SHA256SUMS
```

安装包安装到 `%LOCALAPPDATA%\Programs\FlowVision`，不需要管理员权限，因此应用可自我更新。直接运行构建目录里的 exe 不是受支持的更新安装位置。

## 4. 密钥与故障处理

- 私钥丢失：已安装版本无法验证新更新。只能从备份恢复；没有备份时只能换新密钥，并让用户手动安装一次新版本。
- 私钥泄露：立即生成新密钥对、更新 `mygo.json`、设置新 secret，并发布一个使用新公钥的版本；旧版本会拒绝新密钥更新，需要手动安装过渡版本。
- 更新签名失败：检查 GitHub secret 是否是当前 `mygo.json` 公钥对应的私钥；`mygo build` 会直接报错“does not match updates.publicKey”。
- Release 已发布但版本有问题：不要复用同一个 tag 悄悄替换资产；发布一个更高的修复版本。需要撤回时先在 GitHub 将 Release 标记为 pre-release 或删除，再发布修复版本。
- 仓库必须保持 public，否则 `releases/latest/download` 对应用返回 404，更新检查会失败。
