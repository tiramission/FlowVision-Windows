# 移植说明：从 Swift/AppKit 到 Go + MyGo

本文记录评估依据、两阶段架构、模块对照、原生 UI 的实现方式、算法迁移和 Windows/MyGo 实测坑，便于后续维护或继续补齐功能。

## 1. 两阶段移植路径

原仓库 `FlowVision/Sources` 的实测统计（文件扫描 + 文本计数）：

- 54 个 `.swift` 文件，合计 33,088 行；另有 `Main.storyboard`（113 KB）、6 个 XIB、`.xcstrings` 本地化资源。
- `NSView` / `NSWindow` / `NSControl` 等 AppKit 类型出现 1,427 次；`import AppKit` 54 次。
- CoreGraphics 366 次、FileManager 92 次、ImageIO 49 次、xattr/Finder 标签 22 次、AVFoundation 21 次、FSEvents/DispatchSource 18 次、CoreImage 11 次。
- `Metal`、`vImage`、`QuickLook` 均为 0 次：原项目没有自绘 GPU 管线，图片缩放/合成都交给 CoreGraphics。

结论是必须重写 UI 层，但业务逻辑（瀑布流、排序、缓存、EXIF、导航、文件操作）可以迁移。移植分两步：

1. **1.0.0**：Go 后端 + MyGo 窗口 + WebView2 HTML/JS 前端。先跑通功能，代价是需要 WebView2 Runtime、页面与 Go 通过 `Bind`/`Eval` 通信，且 WebView 事件线程里同步 `Eval` 会自锁。
2. **1.1.0**：同一套 Go 业务层不动，窗口内容换成 `mygo/ui` 原生控件与自绘网格，删除 `web/`、`SetFrontend`、`Bind`、`Eval`、图片自定义协议与回环媒体服务。构建 tag `mygo_nowebview` 让 MyGo 进入 native-only 模式。
3. **1.2.0**：在 1.1.0 的原生 UI 上接入 Onevra，替换默认的冷色控件外观：暖白/暖黑 surface、陶土色 accent、Onevra Sidebar、IconButton、TextBox、Switch、Button、Badge 和 Lucide 图标；照片卡片的颜色、圆角、边框和悬停阴影也使用 Onevra token，但瀑布流仍由 `grid.go` 自绘以保留虚拟化。
4. **1.2.1**：移除系统标题栏与系统窗口按钮，在窗口内容顶部自绘 48 DIP 的 Onevra 标题栏：品牌、标签页、新建和最小化/最大化还原/关闭；保留拖动、双击最大化、Windows 11 snap layouts、系统缩放边缘。
5. **1.2.2**：接入 MyGo 的签名更新与标准化发布：`mygo.json` 配置公开 GitHub 更新源和 Ed25519 公钥；应用使用 `native` updater；GitHub Actions 在 `v*` 标签上构建安装包、签名更新归档和清单并发布。
6. **1.2.3**：自绘标题栏后原生菜单栏只能通过 Alt 调出，主界面看不到“检查更新”；标题栏增加常驻按钮，设置页增加“软件更新”区块，关于窗口也提供入口。

## 2. 当前架构

```
┌──────────────────────── FlowVision.exe（Go，无 cgo，无 WebView2）────────────────────────┐
│ main.go      窗口/单实例/启动路径/菜单安装                                                  │
│ app.go       App/Tab/Viewer 状态、异步加载、历史、选择、设置、缩略图与树缓存                 │
│ view.go      自绘标题栏、侧栏、标签栏、工具栏、内容区、状态栏；Onevra 组件 + ui 控件布局                  │
│ grid.go      虚拟瀑布流；ui.Box.Draw 自绘 Onevra 卡片；命中测试、选择、右键菜单、拖放         │
│ viewer.go    ui.DialogBase 主窗口内查看器；沉浸、指针锚定缩放、长按缩放、侧键翻页、上下边缘浮层 │
│ dialogs.go   ui.Modal + Onevra 设置/重命名/新建/删除/帮助/关于                                │
│ menu.go      mygo.Menu → 直接调用 App（w.Update 回主线程）；帮助菜单的检查更新入口            │
│ update_ui.go 应用内中文更新面板；检查/下载/安装/错误状态；MyGo Updater 签名更新             │
│ 发布         CHANGELOG.md + .github/workflows/release.yml；mygo.json 更新源/公钥            │
│ dir.go/thumb.go/meta.go/video_meta.go/actions.go/settings.go   文件扫描、缩略图、元数据与设置 │
│ win32.go     隐藏属性/回收站、鼠标进入窗口上下边缘检测                                        │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

没有页面 origin、没有 JSON-RPC、没有 `window.fv`。所有交互都在 Go struct 与 `ui` 元素之间完成；菜单回调只投递到 UI 线程，不等待页面。

## 4. 原生 UI 的关键设计

### 4.1 为什么网格要自绘

`ui` 的普通控件适合侧栏、工具栏、对话框，但照片网格有 6,000 项上限，逐项创建 `ui.Box`/`ui.Image` 会带来巨大的构建与布局开销。`grid.go` 因此用：

```go
ui.Scroll(c).TrackScroll(&tab.Scroll).Children(func() {
    ui.Box(c).Height(totalHeight).Draw(a.paintGrid).Children(func() { /* 命中层 */ })
})
```

`buildWaterfall` 先算好每张图的 `x/y/w/h`，`Draw` 只画可见区域的缩略图、占位、视频角标、文件名和选中描边；命中测试把指针坐标减去滚动偏移后在线性表里查找。这样滚动 160 项时仍只有一屏的绘制量。

### 4.2 瀑布流算法

与 1.0.0 的 Web 前端一致，但改成“最短列优先”：

- 列数 = `clamp(内容宽度 / max(目标缩略图宽度, 160), 1, 8)`。
- 每张图宽度 = 目标宽度；高度 = `宽度 / clamp(宽高比, 0.34, 3.2)`。
- 放进当前累计高度最小的列，更新列高；总高度取最高列。
- 缩略图未返回尺寸时按 1:1 占位；尺寸到达后重排，保持滚动位置。

### 4.3 查看器

`viewer.go` 用铺满窗口的 `ui.DialogBase`，背景黑；图片用 `Painter.Transform` 组合 `Scaling → Rotation → Translation`，支持 fit/100%/缩放/旋转/拖动。视频用 `ui.Video` + `video.Open`，播放器在关闭时释放。信息面板异步读取 `MediaSvc.Info`，不阻塞绘制。

### 4.4 菜单与主线程

原生菜单项不再 `evalPage`，直接调用 `App` 方法，并用 `w.Update(fn)` 投递到 UI 线程：

```go
item := func(label, accel string, fn func()) *mygo.MenuItem {
    return &mygo.MenuItem{Label: label, Accelerator: accel,
        Click: func(_ *mygo.MenuItem, w *mygo.Window) { w.Update(fn) }}
}
```

### 4.5 搜索

搜索框是 `ui.TextInput`，绑定 `Tab.Query`。由于输入法组合文本在提交前不会写入指针，工具栏每帧比较 `Query` 与 `Tab.AppliedQuery`，不同则 `refilter()`，这样中文输入法候选上屏后也能过滤。`Ctrl+F` 通过 `ui.Handle.SelectAll` 聚焦并全选，避免 `AutoFocus` 在“已经出现过的持久控件”上不生效的问题。

### 4.6 主题

`mygo.Theme.IsDark()` 在 headless `Tester` 里会阻塞，因此启动首帧从 `c.Theme().Dark` 记录系统深浅色，之后只用 `ui.LightTheme()` / `DarkTheme()` 作为基线，再用 `onevra.Palette(dark)` 覆盖 surface、border、text、accent、focus 等 token。设置里切换主题立即生效；运行中系统主题变化需重启后读取。

`app.uiTheme` 会应用 `c.Preferences()` 的高对比度和文本缩放：高对比度时加深 border、提亮 muted text 并强化 focus ring；文本缩放乘到 `Theme.FontSize`。所有控件、弹窗、原生菜单和自绘网格都读取同一个 `*ui.Theme`，不存在第二套颜色常量。

### 4.7 为什么照片网格不直接用 Onevra 组件

Onevra 的卡片/网格组件适合几十个项目；FlowVision 单目录上限 6,000 项，逐项创建 `ui.Box` 会带来构建、布局与内存开销。因此网格保留 `ui.Scroll` + `ui.Box.Draw` 的虚拟化路径，只把 Onevra 的视觉 token 应用到卡片：

- 卡片是 `th.Surface` 圆角面板，边框 `th.Border`，悬停为 `th.SurfaceHover` + 轻微阴影，选中用 `th.Accent` 3px 描边；
- 图片用 `Painter.Clip` 圆角，视频角标是半透明黑胶囊 + Lucide Play；
- 失败/未知格式显示 Lucide ImageOff/Video/File 占位，而不是黑块；
- 文件名在卡片内裁切，悬停时变为 accent 色。

这样既有 Onevra 的观感，又只画可见区域。

### 4.8 无系统标题栏与自绘窗口控制

窗口不再使用系统 caption。`main.go` 的 `WindowOptions`：

```go
TitleBarStyle: mygo.TitleBarHidden,
TitleBarHeight: 48,
HideWindowButtons: true,
```

`TitleBarHidden` 本身只隐藏标题栏文字与 caption，仍会保留系统按钮；`HideWindowButtons: true` 再隐藏按钮并把 `c.TitleBar()` 置零，因此整条 48 DIP 标题栏都由 `view.go` 的 `titleBar` 绘制。内容顶层变成 `Column(titleBar, Row(sidebar, mainColumn))`，标签条从原来的独立行移入标题栏：

- 左侧品牌：Onevra `Images` 图标 + `FlowVision`；侧栏显示时品牌宽度按 `sidebarWidth` 对齐侧栏区域。
- 分隔线后是原 `tabStrip`：标签、每标签关闭、`Ctrl+T` 新建按钮和横向滚动；标签高度 32 DIP。
- 最右侧 `windowControls`：46×48 DIP 的最小化（`lucide.Minus`）、最大化/还原（未最大化 `lucide.Square`，最大化 `lucide.Copy`）、关闭（`lucide.X`）。关闭按钮 hover 使用 `th.Danger` 红底白图标。
- 所有窗口操作通过 `a.later(action)` 投递到当前 build pass 之后，避免在布局构建中同步关闭窗口。
- `.DragWindow()` 设在标题栏和标签滚动区上，整条空白区可拖动；双击空白标题栏由 MyGo 交给系统最大化。最大化按钮额外调用 `.MaximizeButton()`，以在 Windows 11 上保留 snap layouts。
- `OnMaximize` / `OnUnmaximize` 同步 `app.maximized` 并刷新，`OnResize` 在尺寸变化后刷新；`OnReadyToShow` 用 `win.IsMaximized()` 校正启动状态。

因为系统按钮已隐藏，必须保留自绘的关闭路径；只隐藏 caption 而不画按钮会让窗口无法用鼠标关闭。

### 4.9 签名更新与发布

`mygo.json` 同时承担打包和更新配置：

```json
{
  "out": "build",
  "updates": {
    "publicKey": "<Ed25519 公钥>",
    "github": "tiramission/FlowVision-Windows"
  }
}
```

- `mygo build` 读取 `updates.github` 的公开 Release，生成 `update-windows-amd64.json` 和更新归档，并用 `MYGO_UPDATER_PRIVATE_KEY` 或 `updates.privateKey` 的私钥签名；更新源必须是匿名可读的仓库。
- 应用在 `main()` 中不再注册 `native.Plugin`；`update_ui.go` 直接调用 `mygo.Updater.Check` / `Update.Install`，用 `ui.Modal` 和 Onevra 组件绘制中文更新面板。标题栏、帮助菜单、设置页和关于页都指向同一个入口。
- 启动后延迟 2 秒自动检查一次；只有发现新版本才打开面板。手动检查始终打开面板，并显示“检查中 / 已是最新 / 可更新 / 下载 / 待重启 / 错误 / 不可更新”状态。
- 打包版本从 `mygo.App.Version()` 得到 `mygo.json` 的版本；`devVersion` 只是直接 `go build` 时的兜底。
- GitHub Actions 在 `v*` 标签触发：校验 tag 与版本、创建草稿 Release、`go tool mygo build -platform windows/amd64 -upload`、发布。私钥只进入 `MYGO_UPDATER_PRIVATE_KEY` secret，不进入仓库。
- 安装包安装到 `%LOCALAPPDATA%\Programs\FlowVision`，不需要管理员权限，因此 updater 可以替换安装目录并重启。

开发和测试构建没有更新公钥，updater 会明确提示该构建不能自我更新；这是预期行为，不是发布包缺陷。

### 4.10 标题栏的验证方式

`CapturePage` 只截客户区，能完整看到自绘标题栏；实际窗口截图必须使用 DPI-aware 的 PowerShell，否则 150% DPI 下 `GetWindowRect`/`CopyFromScreen` 会把右侧窗口按钮截掉。验证窗口无系统标题栏时，比较窗口矩形顶边与客户区屏幕坐标：两者基本重合；同时窗口仍保留可拖动的顶边缩放区域。

## 5. 关键算法

### 5.1 缩略图缓存

- 缓存键：`<id>-<bucket>-<mtime>-<size>.jpg`，bucket 为 96/160/240/320/480/640/800/960。
- 失效：缓存 mtime 小于源文件 mtime，或大小为 0。
- 生成：EXIF 方向校正 → `draw.CatmullRom.Scale` → 透明区域合成 `#2a2a2e` → JPEG q84。
- 并发：全局信号量 `min(max(NumCPU,2),6)`；同一缓存路径再加一把 `sync.Map` 里的互斥锁，避免多个网格单元同时生成同一张图、在 Windows 上互相覆盖 rename 导致缓存文件缺失。
- 淘汰：累计写入每 150 次触发一次，按访问时间最旧优先删除到 `CacheLimitMB` 的 80%。

### 5.2 EXIF 方向

手写 TIFF IFD 解析（`meta.go`）：JPEG 的 APP1 → TIFF 头（II/MM）→ IFD0 标签 `0x0112`。方向 5–8 交换宽高，缩略图渲染时按方向做像素变换。

### 5.3 同级文件夹跳转

`FS.Sibling(path, ±1, showHidden)`：读父目录，按名称排序后从当前位置向一个方向线性查找，跳过隐藏目录，用 5 秒缓存“该目录是否含媒体”，避免每次导航递归扫盘；到边界返回 `found=false`。

## 6. Windows / MyGo 实测坑

1. **`ui.Row` 的子 `Column` 只 `Grow(1)` 会在交叉轴居中。** 主列需 `.FillHeight()`，否则标签/工具栏/网格整体垂直居中并上下溢出。
2. **`Painter.Text` 的 `y` 是文本顶部，不是基线。** 文件名原来画在图片下 `+18`、clip 20px，只露上半截；改为 `+4`、clip 22px。
3. **原生 `ContextMenu` 回调里 `RightClicked()` 不可靠。** 右键时菜单先弹出，该次构建里 `RightClicked` 未必为真。改为在 `ContextMenu` 回调中用 `PointerPosition()` 重新 hit-test 目标 tile，再计算 `contextIDs`。
4. **`mygo.Theme.IsDark()` 在 headless `Tester` 中阻塞。** 改为首帧记录 `c.Theme().Dark`，测试不再查询 MyGo 主题。
5. **`TextInput.AutoFocus` 对已经出现过的持久输入框不生效。** 用 `ui.Handle` + `SelectAll` 显式聚焦；同时在每帧比较 `Query` 与 `AppliedQuery`，不依赖 `Changed()` 的消费时机。
6. **`TextInput` 的输入法组合文本在提交前不写入绑定指针。** 因此搜索过滤放在 `AppliedQuery` 比较上；截图中看到的组合串不应被当作最终 query。
7. **并发缩略图 rename 竞争。** 8 个 goroutine 同时请求同一张图时，Windows 上多次 `os.Rename` 到同一目标会互相失败；加 per-path 锁后稳定。
8. **设置弹窗高度。** 720×460 最小窗口下内容会溢出；body 改为 `ui.Scroll`，高度按窗口限制到 520 DIP。
9. **关闭查看器要释放播放器。** `DialogBase`/Esc 关闭后若直接 return，`Player` 仍持有；开头检测 `!Open && (Player != nil || Item != nil)` 时调用 `closeViewer`。
10. **构建 tag 必须带 `mygo_nowebview`。** 不带时 MyGo 默认走 WebView 模式，二进制体积和依赖都不同；release 构建脚本固定带该 tag。
11. **`TextInput.AutoFocus().Submitted()` 不能链式再取 `.Label`。** 先取 `field := ...AutoFocus()`，再设属性，最后调 `Submitted()`。
12. **`c.Size()` 返回 `(float32,float32)`；`BorderStartWidth` 只收宽度，颜色用 `.BorderColor`。**
13. **Onevra `components.TextBox` 的 `Key` 必须设在父容器上。** 直接对已初始化的 `TextBox` 调 `.Key(...)` 会 panic（`Key on a TextInput, whose state was initialized`）；用 `ui.Box(c.Key(...)).Children(...)` 包一层，输入框只负责绑定。
14. **`ui.Tabs` 不适合每标签一个关闭按钮。** Onevra 的 Tabs 组件是纯选择器；多标签需要关闭、溢出滚动和活动标签自动入视野，所以标签条继续用 `ui.Row` + 自定义关闭按钮，仅借用 Onevra 的颜色/圆角/图标。
15. **Onevra 的 Sidebar 使用 `ButtonBase`，不是普通 Row。** 侧栏项要用 `components.SidebarItem`，点击由 `.Clicked()` 读取；文件夹树仍用 `ui.TreeItem`，两者可以并存。
16. **`TitleBarHidden` 不会自动隐藏系统窗口按钮。** 只设 `TitleBarHidden` 时 caption 消失但右上角仍有系统最小化/最大化/关闭，内容会延伸到按钮下方；要彻底换成自绘标题栏，必须同时 `HideWindowButtons: true`，并自己实现三个按钮和关闭路径。
17. **`HideWindowButtons` 后 `c.TitleBar()` 为零。** 不能再按系统按钮占位预留右边距；标题栏高度由 `TitleBarHeight` 与自定义行共同决定，窗口顶部内容从 y=0 开始。
18. **最大化/还原图标不能只靠点击时切换。** 用户还可能双击标题栏、使用 Win+↑/↓ 或 snap；必须监听 `OnMaximize`/`OnUnmaximize`（启动时用 `IsMaximized()` 校正），否则图标会和真实窗口状态不一致。`OnResize` 用于尺寸变化后的重绘。
